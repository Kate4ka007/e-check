# Веб-приложение

Nuxt в гибридном режиме: главная и демо отдаются готовым HTML, остальное —
SPA за сессией. См. [ADR-0016](../../docs/adr/0016-hybrid-ssr-public-pages.md).

## Запуск

```bash
pnpm install
pnpm dev            # http://localhost:3000
```

### Если pnpm запускает скрипты под старым Node

Nuxt 4 требует Node 22. На машинах с Volta бывает, что `node --version`
показывает 22, а `pnpm exec node --version` — 20: pnpm запускается через
`corepack`, а он закреплён в Volta за своей версией Node. Симптом —
`SyntaxError: ... does not provide an export named 'styleText'`.

Разовое обходное решение:

```bash
volta run --node 22.17.1 -- pnpm install
volta run --node 22.17.1 -- pnpm dev
```

Постоянное — перепривязать corepack к текущему Node по умолчанию:

```bash
volta install corepack
```

## Данные

Бэкенда пока нет. Источник данных — `app/composables/useReceiptSource.ts`;
когда появится API, меняется только тело `loadAll`.

Приложение сначала ищет фикстуру из настоящих чеков, а если её нет,
показывает синтетический образец из `app/fixtures/demoReceipt.ts`.

Настоящие чеки — персональные данные и в репозиторий не попадают.
Чтобы посмотреть экраны на реальном ответе модели:

```bash
cd ../../spike
pnpm fixture                                  # все успешные прогоны
pnpm fixture -- --model openai-gpt-4o-mini    # конкретная модель
```

Команда кладёт данные и изображения в `public/.local/` — этот каталог
в `.gitignore`.

## Структура

```text
app/
├── assets/css/       Tailwind и токены темы
├── components/       компоненты экрана проверки
├── composables/      источник данных и перевод
├── fixtures/         синтетический образец чека
├── i18n/             словарь интерфейса
├── layouts/
└── pages/
```

## Тексты

Интерфейс на русском, но тексты вынесены в словарь `app/i18n/ru.ts`
и берутся по ключу через `useT()`. Полноценный модуль i18n не подключён:
приложение за логином, префиксы локали в маршрутах не нужны, а словаря
с подстановкой достаточно. Добавить второй язык — значит добавить файл
рядом, а не искать строки по шаблонам.

## Что уже есть

Экран проверки чека — ключевой по плану, от его удобства зависит ответ
на гипотезу. Редактируется любое поле, распознавание считается черновиком.
Расхождение суммы позиций с итогом показывается как предупреждение и
сохранению не мешает: на реальных чеках бывают округления и скидки на
весь чек.

Список чеков пока служебный — только чтобы попасть на экран проверки.
