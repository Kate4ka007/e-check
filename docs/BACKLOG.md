# Бэклог

Задачи в порядке выполнения. Детально расписаны M0 и M1 — дальше планировать
подробно бессмысленно, потому что результат M0 может изменить всё остальное.

Обозначения: `[ ]` не начато, `[~]` в работе, `[x]` готово.

---

## M0 — проверка гипотезы

Цель: за неделю узнать, распознаются ли реальные чеки достаточно хорошо,
чтобы продукт имел смысл. Плюс убедиться, что деплой работает.

**Здесь не пишется production-код.** Всё, что создаётся в `spike/`, —
одноразовое и будет выброшено. Соблазн «сразу сделать правильно» надо
подавить: цель этапа — получить число, а не начать проект.

### Подготовка данных

```text
[ ] Собрать 30–50 своих чеков: продуктовые, аптека, кафе, заправка, магазин техники
[ ] Включить в набор заведомо трудные: мятые, выцветшие, длинные, с плохим светом
[ ] Сложить в spike/fixtures/private/ (каталог в .gitignore)
[ ] Разметить ожидаемый результат вручную: магазин, дата, итог, позиции
```

Разметка — самая скучная и самая важная часть этапа. Без неё «точность»
будет ощущением, а не числом.

### Скрипт сравнения

```text
[ ] Завести аккаунт OpenRouter, получить ключ
[ ] Проверить в настройках, что обучение на данных отключено
[ ] Написать spike/run.ts: прогон набора через выбранный вариант
[ ] Сохранять ответы в spike/results/ — не тратить лимит на повторы
[ ] Написать spike/score.ts: сравнение с разметкой, подсчёт точности
```

### Варианты для сравнения

```text
[ ] Вариант A: vision-модель, изображение → JSON одним вызовом
[ ] Вариант B: OCR-модель → текст → текстовая модель → JSON
[ ] Вариант C: Azure Document Intelligence prebuilt-receipt (опционально, нужна карта)
```

Вариант C — эталон. Если пропустить, не с чем сравнивать абсолютное качество:
непонятно, «модель плохая» или «задача трудная».

### Итерации по промпту

```text
[ ] Первая версия промпта со схемой ответа и закрытым списком категорий
[ ] Замер точности
[ ] 3–5 итераций: правка промпта → замер → запись результата в таблицу
[ ] Проверить особые случаи: весовой товар, депозит за тару, скидка строкой
```

Каждая итерация записывается: версия промпта, модель, дата, цифры.
Без таблицы правки промпта превращаются в хождение по кругу.

### Скелет и деплой

Параллельно, в свободное от разметки время.

```text
[ ] pnpm workspace, apps/web, apps/api, packages/contracts
[ ] TypeScript, ESLint, Prettier, единый конфиг на монорепозиторий
[ ] Husky и lint-staged
[ ] docker compose: postgres, postgres-test, redis, minio
[ ] NestJS: пустое приложение с /health
[ ] Nuxt в режиме SPA: одна страница
[ ] Выбрать площадки хостинга из бесплатных тарифов
[ ] Задеплоить оба приложения, /health отвечает из интернета
[ ] GitHub Actions: линтер, типы, сборка
[ ] Записать выбранные площадки в OPERATIONS.md
```

### Решение по итогам

```text
[ ] Заполнить таблицу результатов
[ ] Сверить с порогами из PROJECT_PLAN.md, раздел 1
[ ] Зафиксировать выбор EXTRACTOR_KIND
[ ] Записать ADR-0015 с результатами и выбором
```

**Если точность существенно ниже порогов** — остановиться и подумать,
а не начинать M1 по инерции. Варианты: другие модели, платный провайдер
как часть ответа о жизнеспособности, или честный вывод, что гипотеза
не подтвердилась. Последнее — тоже результат, полученный за неделю
вместо трёх месяцев.

## M7 — перед внешними пользователями

**Блокирующий этап.** Ни один пункт не пропускается — триггер описан
в [ADR-0012](adr/0012-deferred-privacy-posture.md).

```text
[ ] EXTRACTOR_DATA_COLLECTION=deny либо платный провайдер с обработкой в ЕС
[ ] Удаление сырых ответов через 30 дней — проверить, что задача работает
[ ] DELETE /me с каскадом, включая объекты в хранилище
[ ] GET /me/export
[ ] Текст о данных на странице регистрации
[ ] Верификация email
[ ] Восстановление пароля
[ ] REGISTRATION_ENABLED=true
[ ] Резервное копирование с проверкой восстановления
[ ] Поиск осиротевших объектов
```

Проверка восстановления обязательна: резервная копия, из которой ни разу
не восстанавливались, резервной копией не является.
