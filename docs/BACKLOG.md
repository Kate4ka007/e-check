# Бэклог

Задачи в порядке выполнения. Детально расписаны M0 и M1 — дальше планировать
подробно бессмысленно, потому что результат M0 может изменить всё остальное.

Обозначения: `[ ]` не начато, `[~]` в работе, `[x]` готово.

---

## M0 — проверка гипотезы

Цель: за неделю узнать, распознаются ли реальные чеки достаточно хорошо,
чтобы продукт имел смысл. Плюс убедиться, что деплой работает.

**Здесь не пишется production-код.** Всё, что создаётся в `spike/`, —
одноразовое и будет выброшено. Соблазн «сразу сделать правильно» надо
подавить: цель этапа — получить число, а не начать проект.

### Подготовка данных

**Параллельно с M1** — не блокирует разработку фундамента.

```text
[~] Собрать 30–50 своих чеков: продуктовые, аптека, кафе, заправка, магазин техники
[ ] Включить в набор заведомо трудные: мятые, выцветшие, длинные, с плохим светом
[x] Сложить в spike/fixtures/private/ (каталог в .gitignore)
[~] Разметить ожидаемый результат вручную: магазин, дата, итог, позиции
```

Сейчас в наборе 3 чека, и все из одной торговой сети: одна вёрстка, одна
валюта, кириллица. Тридцать таких же не добавят знания к трём. Ценность
дают разные сети, электронные чеки, длинные ленты и съёмка под углом.

Разметка — самая скучная и самая важная часть этапа. Без неё «точность»
будет ощущением, а не числом.

Чтобы разметка не превращалась в перепечатывание чека, `pnpm annotate`
заполняет шаблон ответом модели, а `pnpm diff` показывает, где модели
разошлись между собой и сходится ли сумма позиций с итогом. Проверять
глазами нужно прежде всего расхождения. Заполнить и не проверить —
худший вариант: замер тогда сравнивает модель с самой собой.

### Скрипт сравнения

```text
[x] Завести аккаунт OpenRouter, получить ключ
[ ] Проверить в настройках, что обучение на данных отключено — отложено по ADR-0012
[x] Написать spike/run.ts: прогон набора через выбранный вариант
[x] Сохранять ответы в spike/results/ — не тратить лимит на повторы
[x] Написать spike/score.ts: сравнение с разметкой, подсчёт точности
[x] Вспомогательные команды: models, check, inspect, diff
```

Ключ кэша включает модель, вариант и версию промпта: без этого прогон
на другой модели молча возвращал бы предыдущий результат, и сравнение
моделей не работало бы.

### Варианты для сравнения

```text
[x] Вариант A: vision-модель, изображение → JSON одним вызовом
[ ] Вариант B: OCR-модель → текст → текстовая модель → JSON
[ ] Вариант C: Azure Document Intelligence prebuilt-receipt (опционально, нужна карта)
```

Вариант A на трёх чеках отработал без ошибок, поэтому B пока не запускался:
он нужен как запасной путь, если A начнёт спотыкаться на полном наборе.
Выбор модели и параметров вызова — [ADR-0015](adr/0015-vision-model-and-call-parameters.md).

Вариант C — эталон. Если пропустить, не с чем сравнивать абсолютное качество:
непонятно, «модель плохая» или «задача трудная».

### Итерации по промпту

```text
[x] Первая версия промпта со схемой ответа и закрытым списком категорий
[ ] Замер точности на проверенном эталоне
[~] 3–5 итераций: правка промпта → замер → запись результата в таблицу
[~] Проверить особые случаи: весовой товар, депозит за тару, скидка строкой
```

Промпт v2: даты и время разведены по формату явно, схема приводит к нужному
виду то, что можно привести без домысливания (`2026-08-29T22:27:00` → дата,
`19:24:04` → `19:24`, строка `"null"` → `null`). Порядок компонентов даты
при этом не угадывается: перестановка формата допустима, догадка о
содержимом — нет.

Из особых случаев на текущем наборе встретились весовой товар и скидка
отдельной строкой, обе распознаны верно. Депозита за тару в наборе нет.

Каждая итерация записывается: версия промпта, модель, дата, цифры.
Без таблицы правки промпта превращаются в хождение по кругу.

### Решение по итогам

```text
[ ] Заполнить таблицу результатов
[ ] Сверить с порогами из PROJECT_PLAN.md, раздел 1
[ ] Зафиксировать выбор EXTRACTOR_KIND
[ ] Записать ADR-0016 с итоговыми результатами замера
```

Выбор модели и параметров вызова уже зафиксирован в
[ADR-0015](adr/0015-vision-model-and-call-parameters.md), но на основании
трёх чеков одной сети. ADR-0016 подводит итог на полном наборе.

**Если точность существенно ниже порогов** — остановиться и подумать,
а не начинать M1 по инерции. Варианты: другие модели, платный провайдер
как часть ответа о жизнеспособности, или честный вывод, что гипотеза
не подтвердилась. Последнее — тоже результат, полученный за неделю
вместо трёх месяцев.

## M7 — перед внешними пользователями

**Блокирующий этап.** Ни один пункт не пропускается — триггер описан
в [ADR-0012](adr/0012-deferred-privacy-posture.md).

```text
[ ] EXTRACTOR_DATA_COLLECTION=deny либо платный провайдер с обработкой в ЕС
[ ] Удаление сырых ответов через 30 дней — проверить, что задача работает
[ ] DELETE /me с каскадом, включая объекты в хранилище
[ ] GET /me/export
[ ] Текст о данных на странице регистрации
[ ] Верификация email
[ ] Восстановление пароля
[ ] REGISTRATION_ENABLED=true
[ ] Резервное копирование с проверкой восстановления
[ ] Поиск осиротевших объектов
```

Проверка восстановления обязательна: резервная копия, из которой ни разу
не восстанавливались, резервной копией не является.
