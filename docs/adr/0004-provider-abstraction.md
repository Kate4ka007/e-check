# ADR-0004 — Провайдеры распознавания за интерфейсом

**Статус:** принято
**Дата:** 2026-08-30

## Контекст

Какой провайдер распознаёт чеки лучше — неизвестно, это выясняется в M0.
На старте используются бесплатные модели, при переходе к внешним пользователям
провайдер сменится. Кроме того, вызывать платный внешний сервис в каждом
прогоне тестов недопустимо.

То есть провайдер меняется как минимум трижды за жизнь проекта: после M0,
при переходе на платный тариф, и на каждый запуск тестов.

## Решение

Доменная логика зависит только от интерфейса:

```ts
interface ReceiptExtractor {
  extract(input: ExtractionInput): Promise<ExtractionResult>
}
```

Реализации подключаются через DI по значению переменной окружения.
Мок-реализация — полноправная реализация, а не тестовая заглушка.

Двухэтапный вариант (OCR + текстовый парсер) реализуется как композиция
`TwoStageExtractor(OcrProvider, ReceiptParser)` и остаётся за тем же интерфейсом.
Одноэтапный (vision-модель) реализует интерфейс напрямую.

## Альтернативы

**Прямые вызовы SDK провайдера в сервисах** — быстрее написать, но привязывает
доменную логику к формату ответа конкретного провайдера. Смена превращается
в поиск по кодовой базе.

## Последствия

Сравнение провайдеров в M0 сводится к запуску одного скрипта с разными
реализациями. Смена модели в проде — правка переменной окружения. Тесты
детерминированы и бесплатны.

Плата — дополнительный слой преобразования между форматом провайдера и
внутренней моделью. Оправдана трижды по числу смен провайдера.

## Когда пересмотреть

Не пересматривать. Если после долгой эксплуатации останется ровно одна
реализация и появится сильное желание избавиться от слоя — это признак,
что забыли про тесты.
