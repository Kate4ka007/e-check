# ADR-0001 — REST API вместо GraphQL

**Статус:** принято
**Дата:** 2026-08-30

## Контекст

Нужно выбрать стиль API между Nuxt SPA и NestJS. Клиент один, набор операций
предсказуемый и небольшой: аутентификация, CRUD чеков, справочник категорий,
несколько агрегатов для аналитики.

## Решение

REST с версионированием через префикс `/api/v1`.

## Альтернативы

**GraphQL** решает проблему, которой здесь нет: разнородные клиенты с разными
потребностями в данных. При одном клиенте он добавляет схему, резолверы, защиту
от слишком глубоких запросов и заботу о N+1 — без выгоды.

**tRPC** дал бы сквозную типизацию без кодогенерации, но привязывает клиент
к внутренней структуре сервера и плохо сочетается с NestJS. Типизацию мы
получаем иначе — см. [ADR-0009](0009-zod-first-contracts.md).

## Последствия

Простые, кешируемые, отлаживаемые обычным curl эндпоинты. Загрузка файлов
и подписанные ссылки работают естественно. Плата — при росте числа клиентов
появится избыточная или недостаточная выборка данных.

## Когда пересмотреть

Если появится второй клиент с существенно другими потребностями в данных —
например, мобильное приложение, которому нужны другие срезы.
