# ADR-0008 — Nuxt в режиме SPA

**Статус:** заменено [ADR-0016](0016-hybrid-ssr-public-pages.md)
**Дата:** 2026-08-30

## Контекст

Первая версия плана предполагала Nuxt с серверным рендерингом по умолчанию.
Но всё приложение находится за логином: ни одна страница не индексируется
поисковиками и не открывается анонимно.

При этом серверный рендеринг в связке с аутентификацией через HttpOnly-cookie
стоит дорого: нужно пробрасывать cookie в серверные запросы, различать
серверный и клиентский контекст, бороться с двойными запросами и расхождением
разметки при гидратации. Для соло-проекта это заметная доля времени, потраченная
на инфраструктуру вместо продукта.

## Решение

`ssr: false`. Nuxt используется как SPA-фреймворк.

Сохраняются маршрутизация по файлам, автоимпорты, модули, `useAsyncData`,
структура проекта. Теряется только серверный рендеринг, который здесь не нужен.

Сборка — статические файлы. Раздача с CDN, без Node.js-процесса в production.

## Альтернативы

**Полный SSR** — оправдан для публичного контента. Здесь его нет.

**Гибрид через route rules** — рендерить публичные страницы на сервере,
приватные на клиенте. Публичных страниц три: вход, регистрация, лендинг.
Усложнение не окупается; при появлении полноценного лендинга он всё равно
будет отдельным статическим сайтом.

**Vue + Vite без Nuxt** — меньше магии, но пришлось бы вручную собирать
маршрутизацию, автоимпорты и структуру.

## Последствия

Аутентификация становится однозначной: cookie отправляет браузер, серверного
контекста нет. Деплой фронтенда — выгрузка статики. Локальная разработка быстрее.

Плата — пустой HTML до загрузки JavaScript и отсутствие серверного рендеринга,
если он вдруг понадобится. Первое неважно за логином, второе — обратимо
одной строкой конфигурации плюс работа по пробросу cookie.

## Когда пересмотреть

Если появится публичная часть, которую нужно индексировать, — вынести её
отдельным статическим сайтом, а не включать SSR во всём приложении.
