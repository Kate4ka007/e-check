# Журнал архитектурных решений

Каждый файл фиксирует одно решение: что выбрали, почему, и при каких условиях
это стоит пересмотреть. Последнее важнее всего — решение, принятое для проверки
гипотезы, не обязано оставаться верным для продукта.

Решения не удаляются и не переписываются. Если решение отменено — у него
меняется статус, и появляется новый файл со ссылкой на отменённый.

## Формат

```markdown
# ADR-NNNN — Заголовок

**Статус:** принято | заменено ADR-XXXX | отменено
**Дата:** YYYY-MM-DD

## Контекст

Что заставило принимать это решение.

## Решение

Что решили.

## Альтернативы

Что ещё рассматривали и почему не выбрали.

## Последствия

Что это даёт и чего стоит.

## Когда пересмотреть

Конкретный триггер, а не «когда-нибудь».
```
