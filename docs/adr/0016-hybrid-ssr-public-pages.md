# ADR-0016 — Гибридный рендер: HTML для публичных страниц

**Статус:** принято
**Дата:** 2026-09-02
**Заменяет:** [ADR-0008](0008-spa-not-ssr.md)

## Контекст

ADR-0008 выбрал SPA, потому что приложения за логином нечего индексировать.
С тех пор появились публичные главная (`/`) и демо (`/demo`). Их нужно отдавать
готовым HTML: поисковик и превью-бот не исполняют наше клиентское приложение.

Полный SSR по-прежнему дорог в связке с HttpOnly-cookie: проброс cookie на
сервер Nuxt, расхождение разметки, двойные запросы к `/auth/me`. Приватные
экраны в этом не нуждаются. Отдельный статический сайт для лендинга, как
предлагал ADR-0008, раздвоил бы маршруты, словарь и деплой при двух страницах
в том же Nuxt-приложении.

## Решение

Гибрид через `routeRules`:

- `/` и `/demo` — `ssr: true` и `prerender: true`. HTML строится на сборке,
  контент не зависит от пользователя. `ssr: true` указан явно: иначе общее
  правило SPA перекрывает prerender и в `index.html` остаётся пустая оболочка.
- Логин, регистрация и `/receipts/**` — `ssr: false`. Приложение за сессией
  остаётся SPA. Catch-all `/**` не используем — он побеждает `/` и `/demo`.

Аутентификация не меняется: cookie по-прежнему отправляет браузер, плагин
`auth.client.ts` и `fetchMe` работают только на клиенте. Глобальный middleware
на сервере выходит сразу и не ходит в API — иначе сборка prerender упиралась
бы в недоступный бэкенд, а сервер Nuxt начал бы таскать сессионные cookie.

## Альтернативы

**Полный runtime SSR** — HTML на каждый запрос. Для статичных лендинга и демо
лишний Node-процесс и проброс cookie без выигрыша для SEO.

**Отдельный статический сайт** — как предлагал ADR-0008. Два деплоя и две
копии текстов ради двух маршрутов.

**`ssr: true` без prerender** — в dev совпадает с нужным поведением, в
production на Vercel потребовал бы serverless-функцию на каждый заход на
главную. Prerender даёт тот же HTML файлом на CDN.

## Последствия

Поисковик _может_ увидеть заголовок и текст главной и демо в первом ответе,
но индексация сейчас закрыта: `robots.txt` запрещает обход, в HTML стоит
`noindex`. Когда откроем — правим `public/robots.txt` и мета `robots`.
Деплой фронтенда остаётся сборкой Nuxt: prerender кладёт HTML в `.output/public`,
приватные маршруты — SPA-оболочка.

Плата — следить, чтобы публичные страницы не трогали `window` / `document` /
`localStorage` на сервере, и не включать серверную проверку сессии «на всякий
случай». Новый маршрут нужно явно добавить в `routeRules` и, если он гостевой,
в `guestRoutes` middleware: без этого Nuxt возьмёт SSR по умолчанию.

## Когда пересмотреть

Если публичные страницы станут персональными (контент от пользователя) —
тогда runtime SSR и осознанный проброс cookie, а не prerender.
