# ADR-0002 — PostgreSQL и Prisma

**Статус:** принято
**Дата:** 2026-08-30

## Контекст

Данные проекта сильно связаны: пользователь → чек → позиция → категория, магазин.
Основная ценность продукта — агрегации по этим связям. Нужны транзакции: чек
и его позиции обязаны сохраняться атомарно.

## Решение

PostgreSQL как база, Prisma как ORM и инструмент миграций.

## Альтернативы

**MongoDB** позволила бы хранить чек одним документом, что удобно на запись.
Но продукт живёт агрегациями по категориям и периодам, а это ровно то, в чём
реляционная модель сильнее. Плюс нужны внешние ключи и транзакции.

**TypeORM** сильнее в сложных запросах, но слабее в миграциях и типизации.
Для схемы такого размера возможностей Prisma достаточно.

**Drizzle** ближе к SQL и легче, но экосистема вокруг NestJS менее обкатана.

## Последствия

Схема в одном файле, типы генерируются, миграции версионируются. Агрегаты для
аналитики выражаются напрямую в SQL. Плата — Prisma генерирует неоптимальный SQL
для сложных агрегаций; такие запросы придётся писать через `$queryRaw`.

Отдельное следствие: Prisma client extensions дают единую точку для ограничения
выборки по владельцу — см. [SECURITY_AND_PRIVACY.md](../SECURITY_AND_PRIVACY.md).

## Когда пересмотреть

Если запросы аналитики начнут упираться в возможности Prisma настолько, что
`$queryRaw` станет нормой, а не исключением.
